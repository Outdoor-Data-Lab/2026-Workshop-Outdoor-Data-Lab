# Populating the application

## Importing data

In the Django admin interface (<http://localhost:8000/admin/>), open the import
page, click **Add**, select the source and file, then click **Save**. The text
below **Source** describes the expected file format.

| Data | Page | Source | File |
|---|---|---|---|
| OutdoorVision tracks | Traffic › Traffic imports | OutdoorVision | GPKG containing raw tracks |
| Strava Metro | Traffic › Traffic imports | Strava | Annual or daily ZIP file, as delivered |
| Counters | Traffic › Traffic imports | Eco-Compteur | CSV generated by `compteurs_to_csv.py` |
| iNaturalist observers | Traffic › Traffic imports | iNaturalist | iNaturalist export or GBIF download (ZIP) |
| SINP observations | Biodiversité › Observation imports | SINP | CSV exported from the GeoNature synthesis |
| GBIF occurrences | Biodiversité › Observation imports | GBIF | Unzipped GBIF CSV (TaxRef must be loaded) |
| Offers | Outdoor › Offer imports | Offer source | GeoPackage, then **Apply the import** |

The history of all imports is available under Commons › Data imports.

!!! warning

    Do not import sensitive SINP data: sensitivity is not yet supported.

## Computing visitor traffic per grid cell

Counts and scores per grid cell are computed on the fly from the measures. The
cells of each counting object are kept in `traffic.counting_object_areas` by a
database trigger. If ref_geo was loaded or reloaded after the counting objects,
rebuild that table:

```sh
docker compose exec web python backend/manage.py sync_counting_object_areas
```

The grid is the ref_geo area type given by `DEFAULT_GRID_AREA_TYPE` in `.env`
(default `M0.5`, the 500 m grid added by traffic migration 0008; `M1`: 1 km),
among the grids of `AREA_TYPES` (default `M1,M0.5`). After changing it, rerun
the command above (or pass `--area-type M0.5` once) to rebuild
`traffic.counting_object_areas` for the new grid.
